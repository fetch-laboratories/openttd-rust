# Agents run the project; the user sets the goal and is asked for decisions only rarely

The fork is an experiment in autonomous porting. The user does not know Rust, CI or the game's internals well: "I don't know a lick of Rust, and haven't written a line of C++ in 10 years" (2026-10-02). On the first day an agent nonetheless planned for the user to choose new behaviours and steer development.

Agents choose the work, write the process, review, merge and commit. They do not stop for routine approval. The user sets the goal and guides, and is asked for a decision only where it sets the goal or scope, spends money, depends on this machine or is legal ([how the user sorts ownership](README.md#how-the-user-sorts-ownership)).

The user has said so many times. On 2026-10-02: "I told you this will run completely autonomously, but you're trying to get me to drive development", and "do not stop to ask for approvel nor permission to continue." On 2026-10-26: "decisions for me should be very rare." On 2026-11-09, when an agent defended a rule as one the user had approved: "my decisions don't matter! if my decisions are wrong then they need to be corrected!" On 2026-11-12: "I'm here to help and guide because agents do dumbass shit all the time".

Reversing it would change how every role, skill and root procedure works.
